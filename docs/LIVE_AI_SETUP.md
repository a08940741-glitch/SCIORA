# SCIORA — Live AI Setup and First Controlled Test

> **Status (2026-11-21):** a first controlled live test with **Groq** (`openai/gpt-oss-120b`) completed
> all 6 AI calls and passed SCIORA's automatic checks (English only). The first run hit Groq's
> free-tier rate limit at call 5; the remaining calls passed after a pause, and the test now waits
> 20 s between calls. **Anthropic has never been run against the real API.** Teacher review of
> live content is still pending. SCIORA is English-only: prompts require English, and non-English output is rejected.

## 1. Demo versus live

| | Demo mode (default) | Live mode |
|---|---|---|
| Turned on by | nothing (default) | `SCIORA_AI_MODE=live` + the selected provider's key |
| Content | Pre-written English answers for 5 topics and 5 claims | Generated by a real AI model for any question |
| AI calls | None | Yes: to Groq (free tier) or Anthropic (paid) |
| Cost | 0 | Groq free tier: 0 within its limits. Anthropic: paid. |
| Label in the app | "Demo mode…" banner, **DEMO** badges | "Live AI (Groq/Claude)…" banner, **AI-generated (model)** badges, plus a warning not to type personal information |
| If the AI fails | n/a | An error message ("busy, try again", "not configured"…). **Never** replaced by demo content |

The rule-based grading (multiple choice, numbers, algebra), server-side checks of sources, quotes and verdicts, the daily cap and the rate limit work the same way in both modes.

## 2. Environment variables

| Variable | Needed for live? | Meaning |
|---|---|---|
| `SCIORA_AI_MODE` | yes | `demo` (default) or `live`. |
| `SCIORA_AI_PROVIDER` | yes | `groq` (free tier, recommended for the 0 MAD budget) or `anthropic` (paid, default value). An unknown value stops the server at startup; it never switches to another provider. |
| `GROQ_API_KEY` | with `groq` | Server-side only. Must be 20–256 visible ASCII characters with no spaces (shape check only; the value is never printed). |
| `ANTHROPIC_API_KEY` | with `anthropic` | Server-side only. Paid service. |
| `SCIORA_GROQ_MODEL_LEARN` / `_FAST` / `_REASON` | no | Default `openai/gpt-oss-120b` for all three (listed by Groq as a production model with strict structured outputs; re-check Groq's models and deprecations pages). |
| `SCIORA_MODEL_LEARN` / `_FAST` / `_REASON` | no | Anthropic models (defaults `claude-sonnet-5-5`, `claude-haiku-5-5`, `claude-opus-5-5`). |
| `SCIORA_DAILY_LIMIT` | **strongly recommended** | Max AI calls per day for the whole server. `0` = no limit. Use e.g. `20`. |
| `SCIORA_RATE_LIMIT_PER_MINUTE` | recommended | Per-IP requests per minute (default 30). Use e.g. `10` on a shared free tier. |
| `SCIORA_ALLOW_LIVE_TESTS` | for `npm run test:live` | Must be `1`, or the live test refuses to run. |
| `SCIORA_TOKEN_SECRET` | in production | ≥ 32 random bytes (encrypts exercise answer keys). |

Only the selected provider's key is read. A key on its own never enables live mode.

## 3. Setting the key locally (never in the repository)

1. **Who creates the account:** Groq's terms require the account holder to be **18 or older**, so a parent, guardian or teacher must create the Groq account and the API key. Do not create paid plans or enter payment details. Free-tier eligibility and limits are decided by Groq and can change; check the Groq console.
2. Copy `.env.example` to `.env` in the project folder (`.env` is git-ignored; `npm run secret-scan` also checks for keys). Edit `.env`:
   ```
   SCIORA_AI_MODE=live
   SCIORA_AI_PROVIDER=groq
   GROQ_API_KEY=<paste the key here, on your computer only>
   SCIORA_DAILY_LIMIT=20
   SCIORA_RATE_LIMIT_PER_MINUTE=10
   ```
   Never paste the key into chat, code, documents, screenshots or the Drive folder.
3. SCIORA does not load `.env` by itself. Pass it to Node with `--env-file`:

```bash
npx tsx --env-file=.env scripts/live-check.ts
```

```bash
npx tsx --env-file=.env src/server.ts
```

To go back to demo mode, start normally without the env file (`npm start`), or set `SCIORA_AI_MODE=demo`.

## 4. Offline readiness check (no network, no key printed)

```bash
npx tsx --env-file=.env scripts/live-check.ts
```

(`npm run live:check` does the same using variables already exported in your shell.) It prints the mode, provider, models, whether the key is set (never the value), the caps, the host that must be reachable (`api.groq.com`), and warnings. Exit code `0` = ready for a controlled test.

**Safe behaviour without a key:** `SCIORA_AI_MODE=live` with a missing key stops the server at startup with a message naming the variable. In demo mode a key is ignored.

## 5. First controlled live test (owner approval required)

The test makes **at most 6 AI calls**, one after another, and stops at the first error:
lesson → grade a correct written answer → grade a wrong answer → knowledge answer → simplify → evidence analysis.
Each call can be retried once only if the output is malformed (so at most 12 requests); cut-off answers, rate limits and errors are not retried. Wikipedia retrieval (free, no key) also runs if enabled.

Add `SCIORA_ALLOW_LIVE_TESTS=1` to `.env`, then:

```bash
npx tsx --env-file=.env scripts/live-smoke.ts
```

It prints `PASS`/`FAIL` per check, for example:
- lesson served by the live provider, 3 valid exercises, English when English was requested;
- a correct written answer is not marked incorrect, and a **wrong answer is never marked correct**;
- knowledge citations point only to really retrieved sources;
- every evidence quote appears in its retrieved source.

Exit code `0` means every automatic check passed. **Then read the printed content yourself** (is the science right? is the language right?) before saying live AI works. Remove `SCIORA_ALLOW_LIVE_TESTS=1` afterwards.

## 6. Errors you may see

| Message in the app / test | Meaning | What to do |
|---|---|---|
| "SCIORA is busy. Please try again shortly." (HTTP 429, with wait time) | Groq free-tier limit reached | Wait; lower usage; not retried automatically |
| "The AI service is not configured correctly." | Key rejected (401/403) | Check the key in `.env`; create a new key if needed |
| "The configured AI model is not available." | Model id unknown (404) | Check `SCIORA_GROQ_MODEL_*` against Groq's model list |
| "The AI response was too long and was cut off." | Output hit the token limit | Ask a narrower question; not retried |
| "The AI response did not match the expected format." | Invalid JSON or schema after one retry | Try again; if it repeats, the model may not support the schema |
| "The AI service did not respond in time." / "could not be reached." | Timeout or network | Check internet access to `api.groq.com` |
| "SCIORA reached its daily AI usage limit." | `SCIORA_DAILY_LIMIT` reached | Wait until tomorrow (UTC) or raise the cap deliberately |

## 7. Limits and security
- **Free tier:** exact limits (requests and tokens per minute and per day) are shown only in the Groq console and may change. A long lesson may hit a per-minute token limit.
- **Unverified until the first test:** whether Groq accepts these exact JSON schemas, real token usage, and answer quality.
- **Data:** only the student's question, answer or claim text (plus retrieved Wikipedia excerpts) is sent to the provider. SCIORA has no accounts and collects no names; the live banner tells students not to type personal information. Check the provider's data-use terms.
- **Keys:** server-side only, read from environment variables, never sent to the browser, never logged, never included in error messages. `.env` is git-ignored and `npm run secret-scan` checks the repository.
- **Network:** `api.groq.com` must be reachable. (It is blocked in the cloud environment used for development, so the first test must be run on your own computer.)
